# ADR-010: Estadísticas desde un universo de sets por ámbito

Estado: implementada para revisión de Misión 03. Fecha: 2026-10-16.

Las estadísticas necesitan separar inscripciones, placements y sets disputados; los tags no identifican personas y completed no garantiza un encuentro. Se adopta un universo SQL con exactamente una fila por set elegible, ámbito obligatorio de juego, modalidad explícita y rosters validados. Desde allí se obtiene la perspectiva de cada UUID interno para agregados, rivales e historial. PostgreSQL calcula sobre los filtros antes de paginar; las lecturas múltiples de una respuesta comparten REPEATABLE READ. No hay precálculo, rating ni nuevas tablas.

Se consume la clasificación persistida de Misión 02.1. Misión 03 exige además un final sin puntuaciones pero con ganador válido: un helper adicional del clasificador compartido valida exclusivamente esa evidencia, manteniendo intacta la semántica de importación y sus flags. Los candidatos incompletos son la única lectura excepcional de payload; no se desarrolla otro normalizador ni se promueve un resultado por el estado del torneo. Esta decisión supone que el historial competitivo puede declarar elegible un final sin scores que el endpoint de auditoría todavía presenta conservadoramente unresolved. Se devuelve un motivo explícito, se documenta y se prueba esa diferencia. La excepción no habilita ranking_eligible.

El esquema no distingue correcciones administrativas pendientes/confirmadas: cualquier lock de set o mapping start.gg excluye conservadoramente el resultado hasta revisión y desbloqueo. No se inventa otro estado persistido. Dobles conserva rosters y resultados de equipo en un ámbito separado de singles.

Fechas de set usan completed_at; registros sin fecha no pertenecen a un intervalo conocido. Inscripciones y placements se filtran por inicio de torneo, su único timestamp de dominio disponible. Se explicita esta diferencia en contratos y documentación. Todos los intervalos usan instantes con offset y final exclusivo. Sin denominador o dato conocido se devuelve null. El mejor placement no es una clasificación de habilidad.

El costo aceptado es ejecutar consultas pequeñas y repetidas con el mismo CTE, sin N+1. EXPLAIN local y tests de cardinalidad respaldan esta decisión al volumen actual. Si el volumen de finales sin scores o las latencias crecen, revisar un índice o representación de elegibilidad con una migración justificada; no introducirlos anticipadamente. La verificación local no conecta producción ni habilita despliegues.
