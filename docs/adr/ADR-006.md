# ADR-006: Reconciliación de identidades externas

Estado: propuesta implementada para revisión de Misión 02. Fecha: 2026-10-16.

Se conserva el modelo de Misión 01. start.gg Player.id se almacena como player:ID en external_identities, único por proveedor. Participant.id se almacena en tournament_participants.external_id con prefijo de torneo interno estable. Este identificador no se usa como identidad global. Los tags no son claves.

Una identidad externa existente siempre recupera el mismo jugador. Sin identidad global se crea un jugador provisional exclusivo del participante de ese torneo; su repetición recupera la inscripción. Una posterior identidad global contradictoria no fusiona: revierte la importación y registra el conflicto en el job. Dos participantes del mismo torneo que resuelvan a la misma identidad global se consideran conflicto; la revisión humana evita perder evidencia bajo la unicidad jugador/torneo existente.

Los participantes de un mismo torneo pueden integrar distintos eventos. Los equipos conservan cada miembro y su posición; se mantienen FKs y triggers de roster. No se solicita perfil de User ni contacto. Las identidades representan la atribución del proveedor, no identidad legal verificada.

Costo aceptado: una misma persona sin Player.id en dos torneos queda separada hasta revisión explícita. No existe una operación de merge automática ni una interfaz de correcciones todavía.
