# ADR-008: Importación transaccional e idempotente por CLI

Estado: propuesta implementada para revisión de Misión 02. Fecha: 2026-10-16.

Sin autenticación no se expone ninguna escritura HTTP. Una CLI administrativa descarga datos con el cliente asíncrono, valida antes de persistir y publica en una transacción SQLAlchemy síncrona. Next.js consume únicamente la API pública FastAPI.

La conexión dedicada mantiene un bloqueo asesor de sesión por slug durante descarga y escritura. Otro bloqueo serializa importaciones del proveedor en esta base para respetar tasa agregada e identidades. Un job por intento se confirma running antes de descargar; completed se confirma con el dominio, failed después del rollback. La unicidad de external_mappings e identidades determina idempotencia lógica. published impide exponer torneos iniciales incompletos; reimportaciones conservan la versión anterior hasta commit.

Se limita el pool de la CLI a una conexión. No hay colas, worker permanente ni scheduler. Un proceso interrumpido puede dejar un job running histórico, pero PostgreSQL libera los locks y revierte sus cambios; repetir crea un intento independiente. Dry-run valida proveedor sin abrir la base; no estima conflictos locales.

Costo aceptado: no hay checkpoints por página ni ejecución concurrente del proveedor; se vuelve a descargar el torneo completo y se mantiene en memoria. Esto mantiene una frontera de publicación comprensible para el alcance inicial. No habilitar importaciones en producción durante esta misión.
